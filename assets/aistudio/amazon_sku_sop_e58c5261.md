#### （2）核心计算列零维护公式

**① 顶部 5 张全局本位币 KPI 汇总卡片及动态本位币表头**

* **起始单元格**：`B4`（动态货币标题示例）及 `B5`、`D5`、`F5`、`H5`、`J5`（KPI 数值）
* **预期溢出范围**：各自单单元格

```excel
// B4 单元格公式（动态引用参数表本位币符号拼接卡片标题，D4/F4/H4 同理）：
="合并净销售收入 (" & '01_Control_Panel'!$C$6 & ")"

// B5 单元格公式（KPI卡片_合并净销售收入_本位币）：
=IF($C$3="ALL",
    SUM('07_COGS_Profit_Engine'!G6#),
    SUMIFS('07_COGS_Profit_Engine'!G6#, '07_COGS_Profit_Engine'!C6#, $C$3))

// D5 单元格公式（KPI卡片_合并总COGS_本位币）：
=IF($C$3="ALL",
    SUM('07_COGS_Profit_Engine'!K6#),
    SUMIFS('07_COGS_Profit_Engine'!K6#, '07_COGS_Profit_Engine'!C6#, $C$3))

// F5 单元格公式（KPI卡片_合并总运营费用_本位币）：
=IF($C$3="ALL",
    SUM('07_COGS_Profit_Engine'!N6#) + SUM('07_COGS_Profit_Engine'!O6#) + SUM('07_COGS_Profit_Engine'!P6#),
    SUMIFS('07_COGS_Profit_Engine'!N6#, '07_COGS_Profit_Engine'!C6#, $C$3) +
    SUMIFS('07_COGS_Profit_Engine'!O6#, '07_COGS_Profit_Engine'!C6#, $C$3) +
    SUMIFS('07_COGS_Profit_Engine'!P6#, '07_COGS_Profit_Engine'!C6#, $C$3))

// H5 单元格公式（KPI卡片_合并经营净利润_本位币）：
=IF($C$3="ALL",
    SUM('07_COGS_Profit_Engine'!Q6#),
    SUMIFS('07_COGS_Profit_Engine'!Q6#, '07_COGS_Profit_Engine'!C6#, $C$3))

// J5 单元格公式（KPI卡片_合并经营净利率）：
=IF(B5>0, H5 / B5, 0)
```

* **分析应用**：当管理层在 `01_Control_Panel!$C$6` 修改本位币符号（如从 `CA$` 改为 `US$`）或在看板 `C3` 切换目标站点时，顶部 5 张核心财务卡片的货币单位与汇总金额同步刷新，提供一目了然的全局盈利水位。

**② `多站点盈利对比矩阵`（`A10#` 至 `H10#`）**

* **起始单元格**：`A10`（站点列）、`B10`（净销量）、`C10`（净收入）、`D10`（总COGS）、`E10`（毛利率）、`F10`（平台总费用）、`G10`（经营净利润）、`H10`（经营净利率）
* **预期溢出范围**：`A10:H13`（随实际发生销售的站点数自动向下溢出）

```excel
// A10 单元格公式（自动提取活跃Amazon站点）：
=SORT(UNIQUE('07_COGS_Profit_Engine'!C6#))

// B10 单元格公式（站点净有效销售件数）：
=SUMIFS('07_COGS_Profit_Engine'!F6#, '07_COGS_Profit_Engine'!C6#, A10#)

// C10 单元格公式（站点净销售收入_本位币）：
=SUMIFS('07_COGS_Profit_Engine'!G6#, '07_COGS_Profit_Engine'!C6#, A10#)

// D10 单元格公式（站点总COGS_本位币）：
=SUMIFS('07_COGS_Profit_Engine'!K6#, '07_COGS_Profit_Engine'!C6#, A10#)

// E10 单元格公式（站点综合毛利率）：
=IF(C10#>0, (C10# - D10#) / C10#, 0)

// F10 单元格公式（站点Amazon运营总费用_本位币）：
=SUMIFS('07_COGS_Profit_Engine'!N6#, '07_COGS_Profit_Engine'!C6#, A10#) +
 SUMIFS('07_COGS_Profit_Engine'!O6#, '07_COGS_Profit_Engine'!C6#, A10#) +
 SUMIFS('07_COGS_Profit_Engine'!P6#, '07_COGS_Profit_Engine'!C6#, A10#)

// G10 单元格公式（站点经营净利润_本位币）：
=SUMIFS('07_COGS_Profit_Engine'!Q6#, '07_COGS_Profit_Engine'!C6#, A10#)

// H10 单元格公式（站点经营净利率）：
=IF(C10#>0, G10# / C10#, 0)
```

* **分析应用**：将美、加、英、澳四个市场的经营表现统一拉齐到本位币（如 CAD）维度下进行横向比武，直接回答“哪个市场虽然销售额高但被广告和 FBA 费用吃光了利润，哪个市场真正具备高净利率”的核心商业问题。

**③ `月度盈利趋势动态序列`（`A18#` 至 `G18#`）**

* **起始单元格**：`A18`（月份列）、`B18`（月度净收入）、`C18`（月度总COGS）、`D18`（月度毛利额）、`E18`（月度总运营费用）、`F18`（月度经营净利润）、`G18`（月度经营净利率）
* **预期溢出范围**：`A18:G[实际月度数]`（随核算周期内的月份数量自动向下溢出）

```excel
// A18 单元格公式（自动提取核算期内唯一月份并按时间升序排列）：
=SORT(UNIQUE('07_COGS_Profit_Engine'!B6#))

// B18 单元格公式（月度净销售收入_本位币，联动 C3 站点筛选）：
=IF($C$3="ALL",
    SUMIFS('07_COGS_Profit_Engine'!G6#, '07_COGS_Profit_Engine'!B6#, A18#),
    SUMIFS('07_COGS_Profit_Engine'!G6#, '07_COGS_Profit_Engine'!B6#, A18#, '07_COGS_Profit_Engine'!C6#, $C$3))

// C18 单元格公式（月度总COGS_本位币，联动 C3 站点筛选）：
=IF($C$3="ALL",
    SUMIFS('07_COGS_Profit_Engine'!K6#, '07_COGS_Profit_Engine'!B6#, A18#),
    SUMIFS('07_COGS_Profit_Engine'!K6#, '07_COGS_Profit_Engine'!B6#, A18#, '07_COGS_Profit_Engine'!C6#, $C$3))

// D18 单元格公式（月度毛利额_本位币）：
=B18# - C18#

// E18 单元格公式（月度总运营费用_本位币，联动 C3 站点筛选）：
=IF($C$3="ALL",
    SUMIFS('07_COGS_Profit_Engine'!N6#, '07_COGS_Profit_Engine'!B6#, A18#) +
    SUMIFS('07_COGS_Profit_Engine'!O6#, '07_COGS_Profit_Engine'!B6#, A18#) +
    SUMIFS('07_COGS_Profit_Engine'!P6#, '07_COGS_Profit_Engine'!B6#, A18#),
    SUMIFS('07_COGS_Profit_Engine'!N6#, '07_COGS_Profit_Engine'!B6#, A18#, '07_COGS_Profit_Engine'!C6#, $C$3) +
    SUMIFS('07_COGS_Profit_Engine'!O6#, '07_COGS_Profit_Engine'!B6#, A18#, '07_COGS_Profit_Engine'!C6#, $C$3) +
    SUMIFS('07_COGS_Profit_Engine'!P6#, '07_COGS_Profit_Engine'!B6#, A18#, '07_COGS_Profit_Engine'!C6#, $C$3))

// F18 单元格公式（月度经营净利润_本位币）：
=D18# - E18#

// G18 单元格公式（月度经营净利率）：
=IF(B18#>0, F18# / B18#, 0)
```

* **分析应用**：追踪采购批次成本变动与旺季仓储/广告费波动对月度利润率曲线的冲击，帮助管理层及时发现利润率连续下滑的拐点。

* **起始单元格**：`J10`（标准主SKU编码）、`K10`（产品标准名称）、`L10`（净销售件数）、`M10`（净销售收入）、`N10`（总COGS）、`O10`（综合毛利率）、`P10`（经营净利润）、`Q10`（经营净利率）、`R10`（目标净利达标评估）

=IF($C$3="ALL",

    SUMIFS('07_COGS_Profit_Engine'!G6#, '07_COGS_Profit_Engine'!E6#, J10#, '07_COGS_Profit_Engine'!C6#, $C$3))

// N10 单元格公式（主SKU跨市场累计总COGS_本位币，联动 C3 站点筛选）：
=IF($C$3="ALL",

    SUMIFS('07_COGS_Profit_Engine'!Q6#, '07_COGS_Profit_Engine'!E6#, J10#),

// R10 单元格公式（目标净利达标评估 —— 引用参数表 01_Control_Panel!$C$13）：
=LET(

## 第四章：日常使用说明（操作与维护指南）（Step 4）

本章节专为日常负责经营分析的亚马逊运营人员、财务分析人员及管理层编写，全程使用直观的业务操作语言，无需理解复杂公式即可独立完成月度盈利核算与日常维护。

### 4.1 使用方式与工作表视觉规范

1. **如何打开与浏览文件**：
   * 请使用 **Microsoft Excel 365** 或 **Excel 2021 及以上版本** 打开本工作簿，并确保顶部菜单栏“公式 $\rightarrow$ 计算选项”处于 **“自动”** 状态。
   * **色彩视觉隔离规范**：全工作簿严格遵循“**浅蓝色底色 = 手工录入/数据粘贴区**”、“**浅灰色底色 = 全自动公式生成区（严禁手动修改或覆盖）**”的视觉准则。操作人员日常只需在浅蓝色列粘贴或录入数据，浅灰色列会自动向下扩展计算。
2. **如何切换分析视角与查看看板**：
   * **全局核算政策切换**：进入 `01_Control_Panel`（控制面板），修改 `C3:C4` 的起止月份可自由缩放分析时间段；在 `C7` 下拉框可一键对比“按体积 CBM”、“按计费重 KG”或“按采购数量”分摊头程运费对各产品利润的影响；在 `C8` 下拉框可一键切换“历史累计加权平均法”与“最新批次标准成本法”。
   * **管理看板多维钻取**：进入 `09_Profitability_Dashboard`（盈利决策看板），在 `C3` 单元格选择 `ALL` 可查看四站点合并本位币（CAD）总览，选择 `US`、`CA`、`UK` 或 `AU` 可单独审视某站点的月度趋势与 SKU 盈利排行；在 `F3` 单元格选择特定产品类目，右侧《主 SKU 跨市场盈利排行榜》将自动过滤出该产品线的所有商品表现。

### 4.2 标准操作流程（月度核算五步法 SOP）

每月初进行上月跨站点盈利核算时，请严格按照以下 **5 个标准步骤** 顺序操作：

* **第一步：更新源数据（主数据 $\rightarrow$ 汇率与物流 $\rightarrow$ 采购批次 $\rightarrow$ 亚马逊销售与费用）**
  1. **维护新品映射（`02_Product_Master`）**：若上月在任何站点上架了新 MSKU，请在 `A:H` 列（浅蓝区）末尾新增行，填入站点 SKU、所属站点、内部统一标准主 SKU 编码以及单件体积（CBM）和重量（KG）。
  2. **更新当月汇率与货代提单（`06_FX_Allocation`）**：在左侧 `B:D` 列补齐上月 `USD`、`GBP`、`AUD`、`CAD` 折算本位币的财务汇率；在右侧 `G:K` 列录入上月发生的国际货代提单号、账单月份、币种及头程清关总费用。
  3. **录入 Alibaba 采购批次（`03_Procurement_Landed_Cost`）**：在 `A:J` 列末尾追加上月新入库的采购批次发票信息（关联对应的货运提单批次号、入库月份、主 SKU、入库数量、出厂单价、包装费、关税及预处理费）。右侧 `K:Q` 列会自动分摊头程运费并算出该批次的真实单位到岸成本。
  4. **粘贴亚马逊销售与费用报表（`04_Amazon_Sales_Data` 与 `05_Amazon_Expense_Data`）**：从 Seller Central 导出四站点的销售汇总数据与费用明细（结算报表、广告报表、仓储报表），以 **“仅粘贴数值（Paste Values）”** 方式分别追加到 `04` 表的 `A:I` 列末尾和 `05` 表的 `A:H` 列末尾。
* **第二步：刷新状态登记与重新计算（`08_Data_Validation` & `01_Control_Panel`）**
  1. 在 `08_Data_Validation` 左侧 `B6:C11` 区域，将 6 大数据源模块的“最近一次导入日期”更新为当天日期，并将确认状态设为 `已核对无误`。
  2. 进入 `01_Control_Panel`，将 `C4`（报告结束月份）更新为最新核算月份（如 `2026-03`），按键盘 `F9` 键确保全表完成自动重算。
* **第三步：校验关键数据质量指标（`01_Control_Panel` & `08_Data_Validation`）**
  1. 查看 `01_Control_Panel` 的 `F3` 单元格状态指示器。若显示 `⚠️ 发现数据缺口`，请立即切换至 `08_Data_Validation`（数据体检表）。
  2. 检查 `08_Data_Validation` 的 `F列`（孤儿 SKU 清单）是否为空：若有记录，说明销售表里出现了尚未在 `02_Product_Master` 建档的新 SKU，请立即补建档案。
  3. 检查 `H列`（缺失到岸成本清单）是否为空：若有记录，说明某在售主 SKU 尚未在 `03` 表录入任何采购成本，请补录采购批次后再看利润。
  4. 复核 `J列`（被拦截的重复或非权威来源费用清单），确认系统自动过滤的重叠费用符合预期。
* **第四步：查看盈利分析结果与定位问题产品（`09_Profitability_Dashboard` & `07_COGS_Profit_Engine`）**
  1. 进入 `09_Profitability_Dashboard`，先看顶部 5 张 KPI 卡片掌握集团本位币总营收、总 COGS、总平台费用与净利率。
  2. 查看左下方《多站点盈利对比矩阵》与《月度盈利趋势序列》，对比美、加、英、澳四站点的净利率高低及环比变化。
  3. 查看右侧《主 SKU 跨市场盈利排行榜》及 `08_Data_Validation` 的 `L列/N列` 预警，找出标有 `🔴 亏损淘汰预警` 或采购成本大幅上涨的 SKU，进一步到 `07_COGS_Profit_Engine` 查看该 SKU 在具体站点的佣金、广告费与历史成本明细。
* **第五步：导出或分发经营报告**
  1. 在 `09_Profitability_Dashboard` 顶部确认 `01_Control_Panel!F4` 生成的核算口径横幅无误。
  2. 使用 Excel“文件 $\rightarrow$ 导出 $\rightarrow$ 创建 PDF/XPS 文档”，将 `09_Profitability_Dashboard` 与 `08_Data_Validation` 导出为管理层月度经营简报并分发。

### 4.4 系统使用限制与环境依赖

1. **适用业务场景与数据粒度**：
   * 适用于跨多站点（4 个及以上 Marketplace）、多币种结算、从工厂/Alibaba 按批次采购并拼箱发货的跨境电商卖家。
   * 核心核算粒度为 **`月份 × 站点 × 站点SKU`**（汇聚至 **`标准主SKU`**）。若单笔订单流水过细（如每月超过数万笔独立订单），建议在导入 `04_Amazon_Sales_Data` 前先使用 Seller Central 的月度 SKU 汇总报表（如按月度导出 Business Reports 或 Date Range Summary），既大幅减小文件体积，又不损失月度 SKU 级盈利分析精度。
2. **数据量级上限建议**：
   * 为保证打开与重算响应速度在 $1\sim3$ 秒以内，建议 `04_Amazon_Sales_Data` 与 `05_Amazon_Expense_Data` 各自的总行数控制在 **$50,000$ 行以内**（若按 `月份 × 站点 × SKU` 汇总导入，每年仅新增数千行，可轻松连续使用 $5\sim10$ 年）。
3. **必需软件环境**：
   * **必须使用 Microsoft Excel 365（桌面端或网页版）或 Excel 2021 及更高版本**。本工具深度依赖现代动态数组引擎（`LET`、`FILTER`、`UNIQUE`、`SORT`、`XLOOKUP` 及 `#` 溢出引用符）；**严禁使用 Excel 2016/2019 或不支持动态数组的旧版软件打开并保存**，否则动态溢出公式会被破坏。
4. **不支持的场景**：
   * 本工具定位为财务与经营盈利核算引擎，不支持实时库存扣减（WMS）、实时订单履约发货跟踪或多人同时在公式区协同改动结构。

### 4.5 常见故障调整指南（Q&A 排错手册）

#### ❓ 故障一：某个浅灰色公式列的顶部单元格突然显示 `#SPILL!`（溢出错误），整列数字消失了怎么办？
* **原因说明**：`#SPILL!` 表示动态公式想要自动向下扩展生成结果，但在它下方的某个浅灰色单元格里，有人不小心手动输入了文字、空格，或者粘贴了静态数据，把公式向下扩展的“跑道”挡住了。
* **解决步骤**：
  1. 用鼠标左键点击显示 `#SPILL!` 的那个单元格，此时 Excel 会用一圈**虚线框**标出公式试图扩展的区域。
  2. 顺着虚线框往下看，找到非空的阻碍单元格（或者直接选中该列第 7 行到底部的所有单元格）。
  3. 按键盘上的 `Delete`（删除）键清空阻碍内容（注意：**不要删除第 6 行的起始公式单元格**）。清空阻碍物的瞬间，整列数据会立即自动恢复正常显示！

#### ❓ 故障二：在销售表或采购表粘贴了新月份的数据，但 `09_Profitability_Dashboard`（看板）上的数字没有任何变化？
* **原因说明**：通常由以下三个原因之一引起：（1）`01_Control_Panel` 中的“报告起止月份”没有包含新导入的月份；（2）新粘贴的数据行中“A列唯一流水号/批次号”留空了，导致系统判定该行为无效空行；（3）Excel 被设为了“手动计算”模式。
* **解决步骤**：
  1. 先去 `01_Control_Panel` 检查 `C3`（起始月份）和 `C4`（结束月份），确认新数据的月份（如 `2026-04`）处于起止区间内，且格式严格为 `YYYY-MM`（中间为短横线，如 `2026-04` 而非 `2026/4`）。
  2. 检查刚粘贴的数据表（`03`、`04` 或 `05` 表）的 **`A列`（第 1 列）** 是否每一行都有编号。如果 `A列` 为空，请补齐流水号。
  3. 点击 Excel 顶部菜单栏“**公式 $\rightarrow$ 计算选项**”，勾选 **“自动”**，或直接按键盘 `F9` 键强制刷新。

#### ❓ 故障三：修改了 `01_Control_Panel` 参数表中的“共享物流默认分摊基准”，为什么某票货物的运费分摊结果没有变？
* **原因说明**：系统为了兼顾灵活性，在 `06_FX_Allocation`（共享物流池）的 `K列` 设置了“指定分摊方法覆盖”功能。如果某票提单在 `K列` 被人为指定了具体规则（比如填了 `按采购数量`），它会优先执行单票指定规则，而忽略全局默认设置。
* **解决步骤**：
  1. 打开 `06_FX_Allocation` 工作表，查看右侧 `K列`（指定分摊方法覆盖）。
  2. 将希望跟随全局参数变化的提单行的 `K列` 内容清空，或改为 `默认全局`。修改后，旁边 `L列`（最终执行分摊规则）会立即同步为 `01_Control_Panel!$C$7` 的设置，到岸成本也会随之自动重算。

#### ❓ 故障四：某个月份的销售收入或到岸成本折算本位币后全部变成了 `0.00`，或者本位币符号显示异常？
* **原因说明**：当原币种与本位币不同（例如美国站 `USD` 转本位币 `CAD`）时，系统会去 `06_FX_Allocation` 的左侧汇率表中查找“对应月份 + 对应币种”的汇率。如果忘了录入该月份的汇率，未匹配到的汇率默认返回 `0`，导致折算后的本位币金额变为 `0.00`。
* **解决步骤**：
  1. 检查明细表中的 `适用汇率_转本位币` 列（如 `03` 表 `M列`、`04` 表 `M列`、`05` 表 `L列`），找出汇率显示为 `0.0000` 的行，查看其对应的“月份”和“币种”。
  2. 打开 `06_FX_Allocation` 工作表，在左侧 `B:D` 列（月度多币种汇率表）末尾新增行，补录该月份与币种的汇率数值（例如 `2026-04` | `USD` | `1.3650`）。补录完成后，全表本位币金额即刻恢复正常。

## 第五章：整体架构回顾与实施路线总结

### 5.1 整体架构设计回顾

本方案围绕客户“建立跨 Amazon 美、加、英、澳四站点的 SKU 级真实成本核算与盈利决策引擎”的核心诉求，构建了 **4 层 9 表** 的高内聚、低耦合数据架构：

1. **参数与主数据基座（`Sheet 01` & `Sheet 02`）**：通过 `01_Control_Panel` 实现 12 项核心核算政策（期间、本位币、物流分摊基数、历史 COGS 算法、三大费用防重白名单、三大利润与成本预警阈值）的单点配置、全局生效；通过 `02_Product_Master` 消除四站点 MSKU 差异，建立统一的 Master SKU 身份与体积/重量物理基准。
2. **业财数据标准化采集层（`Sheet 03`、`Sheet 04`、`Sheet 05`）**：将 Alibaba 采购发票、关税、预处理费、四站点销售退货记录及多源运营费用统一纳入标准化表结构；在 `05_Amazon_Expense_Data` 独创“唯一记录 ID + 权威报表来源白名单”双重防重有效系数（`K6#`），彻底根治结算表与专项费用表重叠统计的顽疾。
3. **动态分摊与历史成本核算引擎（`Sheet 06` & `Sheet 07`）**：通过 `06_FX_Allocation` 实现月度多币种汇率转换与提单级共享国际运费的按体积/重量/数量自动分摊；通过 `07_COGS_Profit_Engine` 全自动提取活跃 `月份 × 站点 × SKU` 颗粒度，按时间轴动态匹配截至当月的历史累计加权到岸成本，避免用最新批次进价错误覆盖历史销售成本。
4. **数据体检与高层决策看板（`Sheet 08` & `Sheet 09`）**：通过 `08_Data_Validation` 自动捕获孤儿 SKU、缺成本在售品、重复费用、负毛利及采购成本剧烈异动，保障数据可信度；最终在 `09_Profitability_Dashboard` 输出一键切换站点与类目的本位币盈利全景看板。

### 5.2 推荐分步实施顺序

遵循“**先跑通核算口径、再构建看板、最后按需接入自动化**”的稳健实施原则，建议按以下三步落地：

* **阶段一（第 $1\sim3$ 天）：主数据梳理与历史成本基线初始化**：优先协助客户填妥 `01_Control_Panel` 的三大管理会计政策（物流分摊基准、COGS 口径、汇率口径），完成 `02_Product_Master` 四站点 SKU 映射及最近 $3\sim6$ 个月 `03_Procurement_Landed_Cost` 采购批次与 `06_FX_Allocation` 提单运费录入。
* **阶段二（第 $4\sim5$ 天）：Amazon 报表导入与数据体检闭环**：导入四站点销售与费用报表，利用 `08_Data_Validation` 集中清理历史孤儿 SKU 与重叠费用，确保 `07_COGS_Profit_Engine` 产出的每一行 SKU 利润数字经得起财务审计。
* **阶段三（第 $6$ 天及后续日常运营）：看板交付与渐进式自动化**：交付 `09_Profitability_Dashboard` 供管理层开展月度经营复盘；待手工导入流程稳定运行 $1\sim2$ 个周期后，再按需将 `04` 与 `05` 表的浅蓝色输入区对接 Amazon SP-API 导出脚本或第三方连接器，实现无缝升级。
